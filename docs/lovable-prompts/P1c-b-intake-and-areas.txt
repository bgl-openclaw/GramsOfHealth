CLIENT RPCs (client accounts only; staff get { ok: false, message: 'Client accounts only.' })
- my_intake() → {
    ok, status: 'open' | 'submitted' | 'reviewed', can_edit, submitted_at,
    about: { full_name, email (read-only), phone, date_of_birth, sex: 'female' | 'male' | 'other' | 'unspecified', height_cm, activity_level, weight_kg, weight_recorded_on },
    goal: { goal_type, label, detail, target_date, mine } | null,
    requirements: [{ tag_id, label, kind: 'avoid' | 'diet' | 'prefer' | 'other', mine }],
    food_rules: [{ name, rule: 'avoid' | 'dislike' }]   (set by the dietitian; read-only),
    supplements: [{ id, name, dose, timing, mine }],
    answers: { [question_key]: value },
    sections: [{ key, title }]   (about, goals, food, health, lifestyle, consent, in order),
    questions: [{ key, section, label, help, kind: 'text' | 'long_text' | 'number' | 'date' | 'single' | 'multi' | 'yes_no' | 'scale', options: string[] | null, required }],
    options: { sexes: [{ key, label }], activity_levels: [{ key, label }], goal_types: [{ key, label }], avoid: [{ tag_id, label }], diet: [{ tag_id, label }], prefer: [{ tag_id, label }] },
    missing: string[]   (labels still needed before sending) }
- save_my_intake(p_changes) — send ONLY what changed on that step. Keys (all optional):
    about: { full_name, phone, date_of_birth 'YYYY-MM-DD', sex, height_cm, activity_level }
    weight_kg: number
    goal: { goal_type, detail, target_date } | null
    requirements_add: [tag_id], requirements_remove: [tag_id]
    supplements_add: [{ name, dose, timing }], supplements_remove: [id]
    answers: { key: value | null }
  Answer value types: text / long_text / date → string; number and scale (1–5) → number; single → one of options; multi → array of options; yes_no → boolean; null, '' or [] removes the answer.
  Returns { ok: true, message, skipped, intake } (intake = fresh my_intake, use it to refresh) or { ok: false, message } with NOTHING saved (all-or-nothing): show the message on that step and keep the user's input.
  Items with mine = false were set by the dietitian: show them, but don't offer remove (the server keeps them and names them in message).
  After review (can_edit = false) the server only accepts requirements_add with an 'avoid' tag.
- submit_my_intake() → { ok: true, status: 'submitted', message } or { ok: false, message, missing }. Do NOT pass this through unwrapRpc (it would throw away `missing`): read the result and show "Still needed: …" with a link to each step.
- my_areas() → [{ key, title, blurb, icon (a lucide icon name), status: 'coming_soon' | 'live' }]. None of these areas are built yet: render every one as a locked "Coming soon" tile, whatever the status.
- my_details() gains client_status ('new' | 'active' | …), intake_status, intake_missing_count.
