ACCESS (the database enforces it; the UI mirrors it)

1. DATA LAYER (src/lib/clients.ts, typed)
- Clinical (table client_clinical_records): list (recorded_on desc), add, update, delete. Columns: kind 'dexa'|'bloods'|'other', recorded_on (date), summary, measurements (jsonb — store as an array of { name, value, unit }), file_path.
- Files: private storage bucket "clinical-records". Upload to `${client_id}/${crypto.randomUUID()}-${safeFileName}`; only PDF, JPEG, PNG, HEIC up to 20 MB (check before uploading; the bucket also enforces it). View with createSignedUrl(path, 300) opened in a new tab — never a public URL. Deleting a record also removes its file; replacing a file removes the old one.
- Check-ins (client_checkins): list (checkin_on desc), add, update, delete. Fields: checkin_on, feeling, hunger, energy, sleep (1–5), bowels_bristol (1–7), bowels_notes, training, likes, dislikes, changes_wanted, notes. Leave answers ({}) and source ('dietitian') at their defaults.
- Weight with a check-in: after inserting the check-in, if a weight was entered insert client_weights { client_id, weight_kg, recorded_on = checkin_on, checkin_id = new check-in id }. Show that weight on the check-in (join client_weights by checkin_id).
- Plans: list meal_plans where client_id = this client (newest first); "New plan" uses the existing createPlan with client_id, then opens the plan.
