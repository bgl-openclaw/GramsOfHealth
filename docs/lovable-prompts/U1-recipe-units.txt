Grams Editor — U1: recipe unit lists only show measures that work + estimated weights + "Buy as" (owner-approved)

Background: the recipe unit dropdown offers tsp/tbsp/cup/g/kg/mL for EVERY food, even when they give 0 g (e.g. Carrot has no density, so cup/tbsp/mL are meaningless and confuse users). The owner wants each food to offer only measures that actually weigh something, kg removed, estimated weights flagged, and a shopping "Buy as" unit.

The database is already done (migration 0036) — do NOT create migrations. Do NOT edit src/lib/engine.ts, src/lib/adjust.ts or src/lib/energy.ts. What the database now provides:
- unit_conversions.estimated (boolean). true = an import placeholder that was never weighed (e.g. Watermelon "each" = 100 g). Typing new grams on that row clears it automatically; setting estimated = false = "Confirm". Changes are logged in the change log.
- foods.purchase_unit (text | null) — "Buy as". Must be one of that food's conversion units (the database refuses anything else, follows a rename, and clears it if the measure is deleted).
- recipe_verification has new columns estimated_line_count and estimated_ingredients, and its reasons can now include "1 ingredient uses an estimated weight: Watermelon (each)". Recipes with estimated weights are Needs review.
- Conversion unit names are stored trimmed, lower-case, single-spaced; "g", "gram", "grams" and "kg" are refused as measure names (built in).
- No recipe line uses kg any more (the 5 that did are now 1000 g).

2. New file src/lib/units.ts (UI helper — imports from engine.ts, never edits it)
   - unitLabel(u): UNIT_LABEL[u] ?? u, plus "l" → "L" and /^x(\d+)g$/ → "×{n} g".
   - lineUsesEstimate(food, unit, conversions): false for g/gram/grams/kg/x95g; false for tsp/tbsp/cup/ml when food.density_g_ml > 0; otherwise the matching conversion's estimated === true.
   - recipeUnitOptions(food, conversions, currentUnit, defaultSize?) → { value, label, grams, group, estimated }[] with groups in this order:
     a. "Sizes & pieces": every conversion of this food whose unit is NOT tsp/tbsp/cup/ml. "each" first, then by grams ascending. Label "{unitLabel} · {grams} g"; "each" when the food has a default size → "each ({default_size}) · {grams} g". Append " · estimate" when estimated.
     b. "Spoons & cups": tsp, tbsp, cup, ml — ONLY when resolveUnitSource(food, u, conversions).grams > 0. Label "tbsp · 20 g" (+ " · estimate" when lineUsesEstimate).
     c. "Weight": "g" only. kg is never offered.
     d. If currentUnit isn't in the list: if it resolves (e.g. x95g) add it under "Weight" with its grams; otherwise add it under "No weight" labelled "{unitLabel} — no weight", so the existing line still displays it and nothing changes silently.
     No food chosen yet → just "g" (plus the current unit).
     Grams format: ≥ 10 → whole number, else 1 decimal (same as AvailableUnits).
