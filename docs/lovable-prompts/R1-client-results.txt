Clients send their own bloodwork and DEXA scans. The database is live (migration 0050). Do NOT create migrations. Do NOT edit src/lib/engine.ts, src/lib/adjust.ts or src/lib/energy.ts. RPCs return { ok, message, … }; show message word for word when ok is false.

OWNER'S DECISION
- Admins and dietitians already add DEXA, bloods and other records with a file in the client's Clinical section. Keep that.
- Clients can now send their own from the client app.
- A client sees only what they sent, never staff records, summaries or values.
- Interns still have no access to clinical records.

DATABASE (live)
client_clinical_records has new columns:
- source: 'staff' | 'client'
- client_note: the client's note, max 500
- reviewed_at, reviewed_by, reviewed_by_name: when a dietitian or admin marked a client's upload as seen

The database fills these itself:
- Staff records are always 'staff' and seen when added. Never send source, client_note or the reviewed_* fields on insert.
- To mark a client's upload as seen, update reviewed_at to now(). The database stamps who and when, and it can't be un-seen.
- The client's note and the client's file can't be changed (refused with a message). Staff can still edit kind, date, summary and values on it, and delete it.

Storage (bucket clinical-records):
- Client files live at {client_id}/client-{uuid}-{safe file name}.
- A client can upload and open only their own client- files. They can delete one only when it isn't attached to a record.
- Staff files stay at {client_id}/{uuid}-{name}, as today. Clients can't see them.
- Allowed types: PDF, JPEG, PNG, HEIC, HEIF, up to 20 MB (same as today).

RPCs for the client app:
- my_client_id() → uuid of the signed-in client (null if the account isn't linked).
- my_results() → [{ id, kind ('bloods' | 'dexa' | 'other'), recorded_on, note, file_path, sent_at, seen, seen_at, seen_by_name }], newest test date first. Only what this client sent.
- add_my_result(p_kind, p_recorded_on, p_file_path, p_note) → { ok, message, id }.
  - Refuses: a future date, an unknown kind, a file that isn't theirs or wasn't uploaded, the same file twice, a note over 500, or 20 results already waiting.
- remove_my_result(p_id) → { ok, message, file_path }. Only before it's been seen.
