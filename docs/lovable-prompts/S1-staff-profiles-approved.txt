THE OWNER'S DECISIONS
- Two phases. Phase 1 (now): profile details, credentials with expiry status, Team compliance, menu count, own-profile banner. Phase 2 (later, not now): CPD log, email reminders, and nothing about interns losing access.

- Interns keep their access when their placement ends. It is only flagged (see Team compliance).
- Email reminders (phase 2) will go to the person and the practice. Don't build them now.

YOUR SECURITY CONCERN (roles)
Checked. It wasn't exploitable: before this change only admins could write to profiles at all. Now that staff can edit their own row, the database refuses role changes outright. Roles stay on profiles. Every permission check already reads them there, so a user_roles table would mean rewriting every policy for no gain. Specifically:
- Nobody can change their own role, including admins. Hide or disable the role control on your own row in Users.
- Only admins can change roles (unchanged).
- Admin accounts and your own account can't be deleted.
- Signed-out visitors have no write access to profiles.
Database refusals come back as plain sentences (e.g. "You can't change your own role."). Show them as they are.

   A person only sees the types whose roles include their role.

RPCs
- team_compliance() → { ok, people: [...], needs_attention, mine_needs_attention }
  - Each person: { profile_id, name, role, is_me, placement_start, placement_end, placement ('ended' | 'ends_soon' | null; interns only, ends_soon = within 7 days), needs_attention, urgent_count, due_60_count, items: [...] }
  - Each item: { type, label, required, status, due, due_estimated, checked, has_file, id, number, issuer, state, issued_on, expires_on, file_path, checked_at, checked_by_name }
  - Who sees whom: admins see every staff member with full details. A dietitian sees themselves, plus the interns whose supervisor they are (status only: id, number, issuer, state, dates, file_path and checker are null). An intern sees only themselves. Your own row comes first.
  - needs_attention counts the other people who need attention: something expired, due within 30 days, or missing, or a placement that has ended or ends soon. mine_needs_attention is the same for you.
- mark_credential_checked(p_id uuid, p_checked boolean) → { ok, message }. Admins only.

STATUS: take it from the database. Don't recompute it in the app.
Labels:
- current → "Current" (green)
- due_60 → "Due in 60 days" (amber)
- due_30 → "Due in 30 days" (orange)
- expired → "Expired" (red)
- missing → "Missing" (red; only when required)
- not_added → "Not added" (grey, not a warning)
- no_date → "No expiry date" (grey)
Other details:
- due is the expiry date. If there's no expiry but there is an issue date, due is the issue date plus the type's renew period, and due_estimated is true; show "estimated".
- Thresholds use Sydney dates. Something expiring today is still "Due in 30 days" and becomes Expired tomorrow.
- These thresholds are covered by database tests, so the app needs no threshold tests of its own. Test the label mapping instead.

CHANGES TO YOUR PLAN
1. No user_roles table and no has_role() (see above).
2. No staff_cpd table and no CPD tab in phase 1.
3. The APD number isn't a profile column. It's the "apd" credential (number + renewal date), so it gets the same expiry status. The Registration tab shows the apd and ahpra credentials for that person's role, plus the intern fields.
4. Credentials tab = every other credential type for the person's role. One card per type, with its status chip, and "Checked by {name} on {date}" when checked.
5. Menu count: show it to admins only, as the number of people who need attention (needs_attention), like the New sign-ups dot. No menu count for dietitians or interns.
6. Team compliance (Users page, admins): one row per person showing name, role and a chip per item. An "Ended" or "Ends soon" placement chip shows on interns. Admins open a person to see details and the certificate, and to tick "Checked" (mark_credential_checked). Sort people who need attention first.
7. Dietitians: a "My interns" card on My profile, from the same team_compliance() result. It shows status chips only, with no documents and no menu count.
8. Own-profile banner: when mine_needs_attention is true, show one banner on My profile listing what's expired, due within 30 days or missing.
9. Settings → Credentials (admins only): edit label, help, renew months (1–120), which roles are asked, "Required for" roles, order and active. New types get a key made from the label (lowercase, underscores, starting with a letter, unique). Show the key nowhere, and never change it. Every type is optional today; leave required_for empty unless an admin ticks it.
10. Name shown everywhere: preferred_name if set, else full_name. team_compliance already returns it as name.
