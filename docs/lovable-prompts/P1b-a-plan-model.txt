Owner's rule for this work: a plan looks set. Each slot shows one choice. Alternatives sit behind a Swap button and are only used if needed.

DATABASE (live)

meal_plan_items has new columns:
- food_id, quantity, unit
  - An item is EITHER a recipe (recipe_id, as today) OR a food (food_id + quantity + unit, recipe_id null).
  - Food items have no servings_override and no profile_id.
- boosts_item_id: a top-up. A food added to a recipe item on the same day ("extra 100 g chicken in this salad").
- batch_group, batch_role ('cook' | 'eat'): leftovers. Part B builds the screens; for now show them correctly if present.
- option_of: an alternative for another item in the same day and slot.
  - Never counted in day totals, the weekly average or shopping.
  - Hidden behind Swap.
  - An alternative can't itself have alternatives, can't be a leftover and can't be a top-up (the database refuses).

meal_plan_item_deltas (id, item_id, line_ref, kind 'quantity'|'swap'|'remove'|'add', base_food_id, base_quantity, base_unit, new_food_id, new_quantity, new_unit, position, source):
- Ingredient changes for ONE plan item.
- Same shape as recipe_profile_deltas, applied AFTER the item's profile.
- Quantities are whole-recipe quantities, like profiles.
- Part B writes these; in part A, apply them wherever nutrition or shopping is computed.

meal_plan_slot_states (meal_plan_id, day, meal_slot, state 'free_choice'|'empty'|null, reason, locked):
- Per day and slot. Rows exist only for slots that aren't normal.

meal_plans has new columns:
- report, report_at: the generator's report. Nothing writes it yet.
- review_notes, confirmed_at, confirmed_by_name: set only by confirm_plan, in part B.

client_meal_slots.energy_share: percent of the day for that slot. Null means the default (breakfast 25, lunch 30, dinner 30, snacks 15 shared between snack slots).

RPCs:
- publish_meal_plan(p_plan_id, p_snapshot, p_release_on date default null). The client sees the version from p_release_on (Sydney date); null = straight away. The message says "The client sees it from …" when a future date was given.
- plan_publish_check gains these blockers (show them as they are):
  - leftovers that don't match
  - a top-up on another day
  - an alternative not in its meal's slot
  - food in a slot marked free choice or empty
  - "Review the planner report and confirm the plan before publishing." (only when report is set)
